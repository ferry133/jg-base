- [x] 4.6 Confirmed 2026-08-11 on both arms the task allows.
  **By omission**: `talos_mcp_server.py` declares exactly four `@app.tool()` functions — `get_node_status` (`version --short`), `get_etcd_members` (`etcd members`), `get_link_status` (`get links`), `get_service_logs` (`logs`). All four are read-only talosctl subcommands. `_run()` carries no decorator, so it is not reachable as a tool. Argument injection cannot reach a mutating verb either: argv is built as a list handed to `subprocess.run` (no shell), and the subcommand verb is a literal that precedes every caller-controlled value, so `link_id`/`service` can only ever become arguments *to* a read verb, never replace it.
  **Server-side**: the credential's `os:reader` ceiling was already shown to reject the most sensitive admin RPC in task 1.2 (`talosctl config new` → `PermissionDenied: not authorized`), independent of what this code asks for.
- [x] 4.7 (found during 4.4/4.6) `talos_mcp_server.py` has a `TALOS_NODES` allowlist that the pipeline never sets, so `KNOWN_NODES` is empty and the check is inert — the agent can name any IP. **Decided: leave it optional and off, and fix the docs instead.** It was never the security boundary: the credential is an Omni Reader-role SA bound to one cluster, so an IP outside that cluster is refused server-side either way. Wiring it would mean a hand-written list (Omni clusters render `nodes: []`, so nothing can derive it), which goes stale on node replacement and would then refuse the query during exactly the incident this sidecar exists for — a git round-trip to fix, which is the operator involvement the change set out to remove. Documented as optional-and-not-a-boundary in `talos_mcp_server.py`'s docstring and `k8scc/CLAUDE.md`'s env table.
